## 0. 一页摘要（先看这段就够）

**问题**：想打一局格斗，要么装几十 GB 的客户端，要么忍受云游戏延迟；网页上的格斗 demo 大多没有帧数据和防御规则，只能看不能玩。

**方案**：零依赖、打开即玩的浏览器 2D 格斗。三局两胜、帧数据驱动、CPU 对手、本地双人，源码 MIT。

**目标**：从打开到进入对战 P95 < 5 秒；首局完成率 ≥ 60%；稳定 60fps；零 runtime 依赖。

**非目标**：联机对战、移动端触屏、角色选择、养成/付费、排行榜、回放。

**六项需求**：R1 对局流程 · R2 移动与场地 · R3 攻击与命中 · R4 必杀与气槽 · R5 CPU 对手 · R6 输入与双人。

## 1. 背景与问题

### 1.1 现状

- 商业格斗游戏集中在主机/PC 客户端，安装成本高、启动链路长。
- 网页格斗多为技术 demo：能移动、能攻击，但缺少起手/判定/收招帧、防御规则、连段递减——「看起来像」但「打起来不对」。
- 想学习格斗游戏实现的人，缺少一份**短小、可运行、可读**的参考实现。

### 1.2 用户损失

| 场景 | 损失 |
| --- | --- |
| 午休 5 分钟想打一局 | 下载/更新动辄 30 分钟，放弃 |
| 想研究格斗逻辑 | 商业引擎黑盒；开源 demo 缺帧表与边界规则 |
| 想给朋友展示 | 需要对方装客户端/注册账号 |

### 1.3 证据与假设

- 已上线的 live demo 与 GitHub 仓库已验证「静态托管 + 零依赖」可行（工程事实）。
- 「首局完成率 60%」为 v1.0 目标假设，尚无线上埋点，发布后以真实数据校准（见第 6 节）。

## 4. 需求（六项）

> 每项包含：描述、优先级、验收标准（Given/When/Then）、关键边界、度量。
> 所有帧数与数值均来自 `src/config.js`，可直接对照代码验收。

### R1 对局与回合流程（P0）

**描述**：三局两胜；每局 99 秒；KO 或时间到结束本局；先赢 2 局者获胜；平局不加分并进入下一局。

**验收标准**

1. Given 新对局启动，When 进入战斗，Then 先展示 `ROUND n` 96 帧，随后显示 `FIGHT!` 并开始计时。
2. Given 一方 HP 归零，When 本次命中结算完成，Then 进入 `K.O.` 阶段（132 帧），胜者局数 +1。
3. Given 计时归零且双方 HP 不等，When 结算，Then HP 高者获胜；HP 相等则判平局，双方均不加分。
4. Given 某一方局数达到 2，When 本局结束，Then 比赛结束，展示胜者，按 `Enter` 可重开。
5. Given 平局，When 进入下一局，Then 回合数 +1，双方 HP 重置，**气槽保留**。

**关键边界**

| 边界 | 期望行为 |
| --- | --- |
| 双 KO（同帧双方 HP ≤ 0） | 平局，无人加分，进入下一局 |
| KO 与时间到同帧 | **KO 优先**（先结算命中，再判时间） |
| 比赛结束后继续操作 | 冻结对局，仅响应 `Enter` 重开 |
| 连续平局 | 回合数持续累加，不设上限 |

---

### R2 移动、跳跃与场地边界（P0）

**描述**：地面左右移动、跳跃、下蹲；空中可横向修正、可出一次空中攻击；双方有推箱、场地有左右墙。

**验收标准**

1. Given 角色在地面，When 按下跳跃，Then 以初速 -15.6（KAI）/ -15.2（RIN）起跳，重力 0.82/帧。
2. Given 角色在空中，When 按左右，Then 横向速度变为 ±角色速度 × 1.05；同一跳内空中攻击只能用一次。
3. Given 双方距离 < 54，When 同在地面，Then 各推开一半，永不重叠。
4. Given 角色到达世界边界 48 / 1552，When 继续移动，Then 位置被钳制，不能越界。
5. Given 下蹲，When 受击判定，Then 受击框高度从 150 降为 96（可用下段惩罚站姿）。

**关键边界**

| 边界 | 期望行为 |
| --- | --- |
| 空中二次跳跃 | 不允许 |
| 落到地面瞬间 | 立即恢复地面状态，清空中攻击标记 |
| 一方在空中 | 不做推箱分离 |
| 贴墙被击退 | 钳制在墙内，不穿模 |

---

### R3 攻击体系与命中结算（P0）

**描述**：六种攻击（轻拳/重拳/踢/下段/跳跃攻击/必杀），全部由帧数据驱动；命中、防御、击倒、连段递减按表结算。

**帧表（必须逐帧一致）**

| 招式 | 起手 | 判定 | 收招 | 伤害 | 命中硬直 | 防御硬直 | 特性 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 轻拳 `lp` | 4 | 3 | 7 | 26 | 13 | 9 | 最快 |
| 重拳 `hp` | 9 | 4 | 17 | 64 | 18 | 12 | 主力 |
| 踢 `kick` | 12 | 5 | 19 | 82 | 20 | 14 | 击倒 |
| 下段 `low` | 8 | 4 | 14 | 38 | 14 | 10 | 必须蹲防 |
| 跳跃攻击 `jumpAtk` | 5 | 8 | 8 | 52 | 16 | 10 | overhead |
| 必杀 `special` | 12 | — | 22 | — | — | — | 生成投射物 |

**验收标准**

1. Given 站立轻拳，When 第 5–7 帧，Then 判定框生效（起手 4 / 判定 3 / 收招 7）。
2. Given 任何攻击，When 命中，Then 伤害 = 基础伤害 × 连段系数，系数 = `max(0.4, 1 - 已连段数 × 0.07)`。
3. Given 对手站防且招式非下段/overhead，When 命中，Then 伤害 0，进入对应 `blockstun`。
4. Given 踢命中，When 结算，Then 击倒：躺地 42 帧，起身 18 帧无敌。
5. Given 下段，When 对手站防，Then **命中**（下段必须蹲防）。
6. Given 跳跃攻击，When 对手蹲防，Then **命中**（overhead 必须站防）。

**关键边界**

| 边界 | 期望行为 |
| --- | --- |
| 同一次攻击的判定窗口 | 只结算一次（`hitDone`），不重复扣血 |
| 空挥 | 不消耗气、不产生命中 |
| 双方同帧互击 | 按固定顺序结算（P1 先），不出现双结算异常 |
| 起身无敌期间被追击 | 不判定命中 |
| 连段计数 | 54 帧内无新命中则清零 |

### R4 必杀技、气槽与飞行道具（P0）

**描述**：波动（↓↘→ + 攻击）与超杀（↓↘→↓↘→ + 重拳）生成投射物；超杀消耗 100 气；投射物有独立生命周期与削血。

**验收标准**

1. Given 地面且指令成立，When 必杀进入第 13 帧，Then 生成波动：速度 9.2、伤害 72、被挡削血 10、寿命 120 帧。
2. Given 气槽 = 100，When 输入超杀，Then 气槽归 0，生成超级波动：速度 12.5、伤害 210、被挡削血 34。
3. Given 气槽 < 100，When 输入超杀，Then **不触发**超杀，降级为普通攻击或无效输入。
4. Given 波动命中，When 结算，Then 攻击方 +10 气；被防 +4 气。
5. Given 投射物飞出屏幕或寿命耗尽，When 更新，Then 实体销毁，不残留判定。

**关键边界**

| 边界 | 期望行为 |
| --- | --- |
| 同一投射物 | 只判定一次，命中即销毁 |
| 双方投射物相遇 | v1.0 不互相抵消（各自独立） |
| 超杀期间被击倒 | 已生成的投射物继续飞行 |
| 气槽上限/下限 | 钳制在 0–100，不溢出 |

### R5 CPU 对手（P0）

**描述**：可战胜、不作弊、行为可读的 AI：前压、立回、防空、防御、发波、超杀。

**验收标准**

1. Given 距离 > 320，When AI 决策，Then 持续前压，并按冷却概率（冷却 80 帧）发波。
2. Given 对手跳入且距离 < 180，When 冷却结束，Then 55% 概率用重拳防空。
3. Given 对手正在攻击且距离 < 170，When 决策，Then 62% 概率防御（站/蹲随机）。
4. Given 气槽满且距离 < 160，When 决策，Then 14% 概率放超杀。
5. Given 任何时刻，When AI 行动，Then 不读取玩家输入、不使用超出玩家可用的招式。

**关键边界**

| 边界 | 期望行为 |
| --- | --- |
| 攻击冷却 | 出手后进入冷却，避免无限连 |
| 被击倒/硬直 | 不操作，等待恢复 |
| 投射物来袭 | 有概率防御或跳过 |
| 难度参数 | 通过 `difficulty` 缩放，默认 1.0 |

---

### R6 输入系统与本地双人（P0）

**描述**：键盘映射、指令识别、双人同屏、暂停/重开/静音。

**键位**

| 动作 | P1 | P2 |
| --- | --- | --- |
| 移动 | A / D | ← / → |
| 跳 / 蹲 | W / S | ↑ / ↓ |
| 轻拳 / 重拳 / 踢 | J / K / L | 小键盘 1 / 2 / 3（或 N / M / ,） |

**验收标准**

1. Given 地面按 J，When 非下蹲，Then 出轻拳；下蹲时按 J 则出蹲姿轻拳。
2. Given 在 26 帧内完成 ↓↘→ 并按下攻击，When 指令识别，Then 触发波动（成功一次后清空指令缓存）。
3. Given 连续点击攻击键，When 长按不放，Then 不重复触发（仅按下沿生效）。
4. Given P2 使用方向键 + 小键盘，When 操作，Then 与 P1 完全独立、互不干扰。
5. Given 对局中按 Esc，When 触发，Then 暂停；按 R 重开；按 M 静音；暂停时按 Q 回标题。

**关键边界**

| 边界 | 期望行为 |
| --- | --- |
| 浏览器默认行为 | 方向键/空格不滚动页面 |
| 窗口失焦 | 自动暂停，防误操作 |
| 指令窗口 | 超过 26 帧或超过 12 个方向记号则失效 |
| 双人键位冲突 | 两套键位无交集 |

## 7. 依赖与风险

**依赖**

- 静态托管（GitHub Pages），无后端、无数据库。
- 浏览器能力：Canvas 2D、WebAudio、ES modules。
- 无第三方 runtime 依赖。

**风险**

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 移动端无法操作 | 社交分享转化低 | 页面与文案明确「需键盘」；后续做观战模式 |
| 格斗门槛高 | 首局流失 | 标题页给操作表；CPU 默认难度可胜 |
| AI 强度失衡 | 挫败或无聊 | 难度参数化，按 3 局胜率调 |
| 浏览器音频策略 | 无声或报错 | 首次交互后再初始化 AudioContext |
| 单文件过大/首屏慢 | 转化下降 | 图片懒加载、代码分模块、gzip |
